**A yes/no can name its sides.** `{"type": "noul", "labels": {"false": "calm", "true": "urgent"}}` reaches laya as written, as laya's `noul` has taken since laya-mlx 0.3.0. Exactly those two keys, distinct non-empty strings, or the question is refused with laya's wording. It is not measured: describing the sides of a yes/no hurt before (FINDINGS §22). A labelled yes/no is asked as written, not rewritten as a no/yes choice (the rewrite would drop the labels), so on base Laya it can follow its own labels instead of the text. Jev has no such field and is refused it.

Injection moved from 0.914 to 0.900 (yes/no) and from 0.805 to 0.795 (choice), both inside their intervals; the same commit on 0.2.0 gives the old numbers, so the change is the dependency's. laya-mlx 0.3.0 also stopped misreading some shell commands as French; verdict's code filter stays, since on 3,000 real commands the guesser still flagged 88 and the filter cleared all of them.

**If you import verdict's internals.** The public paths are unchanged (`verdict.sdk`, `schema`, `client`, `api`, `config`, `library`, `cli`), and `verdict.backend_jev` and `verdict.backend_systemone` still import. The rest moved into packages: `backend`, `backend_mlx`, `engine` and `capabilities` are now `verdict.backends.base`, `.mlx`, `.engine` and `.capabilities`; `cascade`, `calibrate`, `hierarchy`, `switch`, `router` and `rank` are under `verdict.judge`; `bench`, `router_eval` and `metrics` are under `verdict.evaluation`. The refit tool is `python -m verdict.evaluation.router_eval --refit`. The command line and `verdict docs` are unchanged.

**Docs moved** into `docs/usage/`, `docs/design/` and `docs/research/`, with an architecture diagram in `docs/design/`. Old GitHub links to `docs/<name>.md` no longer resolve.

For contributors: a release page is now `docs/release-notes/vX.Y.Z.md`, published as written, and the workflow refuses a tag without one. `tests/` mirrors the source layout, and `configs/` and `cloud/` live under `training/`.
