Fixes from an audit of the tool's implicit state machines: places where a status was tracked by a flag, a file or an exit code and could end up saying the wrong thing. No model change; the scorecard is identical to v0.10.1.

**Answers and exit codes**

- `verdict cascade`: a state whose escalation failed was reported as never sent. It now counts as sent, the summary says how many sent states failed, and each row lists the questions tried in a new field, `escalation_attempted`. `escalated` still means "answered by the second server".
- Exit status 1 is an answer (`ask --cut`: no; `route`: big; `update --check`: behind; `bench --verify`: regressed). An unexpected failure used to exit 1 too. It now prints its traceback and exits 2, with error code `internal`.
- `ask --cut FILE` with a fit that has no cut (a choice fit) printed a probability and exited 0, which reads as "yes". It is now a usage error. A fits file that is not an object of fits is a usage error too.
- A yes/no that verdict rewrites as a choice lost its `truncated` mark on the way back. It keeps it.
- `cascade` without `--check` and `route --batch` without `--quiet` print JSON, so their errors are now also `{"error": {...}}` on stdout.

**`update`, `init`, `serve`**

- `verdict update` installs the newest tag that has a published GitHub release, so a tag whose release was refused is skipped. Off GitHub, or when GitHub does not answer, it uses the newest tag as before.
- In a checkout, `verdict update` syncs the environment on every run. A sync that failed after a successful pull was never retried, because the next run saw nothing to pull.
- `verdict init` dropped `[systemone]` when it rewrote a config, and moved the config to another port when its own server was holding the configured one. Both are fixed.
- `verdict serve` printed "it binds to localhost" for any `--host`. A non-loopback host now gets a warning that names it.
- An empty `$VERDICT_SYSTEMONE_URL` switches off a remote URL that a config file set, so one run can stay local.
- A server that starts in the middle of a run is asked what it fronts, so a proxy stops getting Laya's yes/no rewrite and 20-option cap.
- Waits between retries to a remote server are capped at 60 seconds, whatever its `Retry-After` says.

**The release gate and the training pipeline**

- `bench --verify` compares a scorecard with an earlier one of the same model, bits and budget, and fails a suite whose metric changed.
- The split stage reuses the seed it recorded, so adding states cannot move the test set, and refuses a rerun with another seed or other fractions.
- A training checkpoint records the items it was made from, and `--resume` refuses one made from other items.
- The pipeline exits 1 when labels failed, counts failed calls toward the cost cap (`failed_spend_usd`), retries a teacher's transport error once, writes generated states as they are accepted, and stops when a generation run accepts nothing.
- The router probability cache is keyed to the prompt text, the question bank and the token budget, so an edited prompt is measured again.

Also in this release: FINDINGS §63 (a trained classifier needs about 400 labels per class to match zero-shot Laya where Laya is good, and LightGBM adds nothing over a logistic head), with the matching advice in the guide.

Install: `uv tool install --python 3.11 'verdict[mlx,laya] @ git+https://github.com/iksnerd/verdict.git@v0.10.2'`, or `verdict update`.
